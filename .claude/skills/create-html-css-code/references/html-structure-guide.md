# HTML Structure Guide

HTML 작성시 참고할 가이드.

## 핵심 규칙
- W3C HTML Validation을 통과할 수 있도록 작성.
- 디자인에 없는 UI는 임의로 생성하지 말 것.(ex. 더보기나 전체보기)
- 인라인 스타일은 쓰지 않는다 — 어떤 셀렉터보다 우선해 `!important` 없이는 CSS 로 덮을 수 없다. 아래 경우만 예외다
  - ex 1. progress bar 형태 ui 에서 스크립트가 제어하는 width 값
  - ex 2. 차트 영역의 임시 background-color(아래 id 규칙의 차트 영역 참고)
  - ex 3. 여러 곳에서 공통으로 쓰는 UI 가 스타일을 바꿀 CSS 변수를 열어 둔 경우, 한 곳만 값이 다르면 그 변수만 인라인으로 준다(ex. `style="--card-cols: 4"`). 같은 값을 여러 곳에 주게 되면 클래스로 묶어 CSS 에서 재정의한다
  - ex 4. 표 열 너비(`<col style="width:…">`)
- 스크린 리더 접근성
  - 논리적인 읽기 순서로 작성(예: 더보기·전체보기 등 추가 콘텐츠를 보여주는 버튼은 HTML 가장 마지막에 배치).
  - 아이콘으로만 된 더보기·전체보기 버튼에는 title 속성으로 설명 제공(예: title="공지사항 더보기", title="자주하는 질문 더보기").
- 강조 태그는 **보이는 모양이 아니라 의미로** 고른다
  - `strong` : 중요함·심각함을 나타낼 때 (문장 안에서 핵심 정보를 짚어줄 때)
  - `em` : 문맥상 어조를 강조할 때 (읽을 때 힘주어 읽는 부분)
  - `b` 태그는 사용하지 않음 (중요도를 전달하지 못해 스크린 리더가 강조로 읽지 않음)
  - 의미상 강조가 아니라 시각 효과만 필요하면 `span` + 클래스
- 최상위 섹션은 항상 `section` 태그로 쓰고(제목이 안 보이면 `h2`를 blind 처리), 그 아래 의미 단위 영역은 `div` + `area_` 계열 클래스로 잡는다.
- 같은 구조가 반복되면 div 나열 대신 `ul > li`로 잡는다. li에 클래스를 안 걸어도 되고 목록이라는 의미도 산다.
- li, dt, dd 태그에는 class를 붙이지 않는다. 
  - **예외는 하나뿐 — 형제 중 일부만 다를 때, 그 항목을 구별하는 모디파이어 클래스**(ex. `<li class="point">`, `<li class="on">`)
  - 판단은 **"이 클래스를 모든 li 에 붙여야 하나"** 로 한다. 전부 붙어야 하면 위반이고, 일부에만 붙으면 예외에 해당.
  - 예외로 붙일 수 있는 건 모디파이어뿐이다.
  - `:first-child`·`:nth-child` 로 같은 모양이 나와도, **순서가 아니라 데이터로 정해지는 구별이면 클래스를 쓴다**(강조 카드가 2번째로 내려가도 강조가 따라와야 한다)
- ul, ol 태그는 list_ 접두사 사용.
- id는 camelCase 사용(ex. 레이어 팝업 등 스크립트가 참조하는 id). 예외 — label 의 for·input id 연결이나 id·aria 속성 연결에서 같은 의미의 UI 가 반복돼 두 단계 번호가 필요하면, camelCase 이름 뒤 번호를 하이픈으로 잇는다(ex. tabPanel1-1, checkAgree1-2)
- 라이브러리나 기타 스크립트가 참조할 수 있는 구조엔 id 값을 적용(ex. 차트 라이브러리)
  - 차트 영역은 빈 구조로 잡아 개발에 전달한다 — 높이 등 최소한의 틀만 CSS 로 작성하고, 영역을 확인할 수 있게 임시 background-color를 인라인으로 넣는다
- 링크와 버튼은 **보이는 모양이 아니라 동작으로** 고른다 — 페이지를 이동하면 `a`, 이동 없이 화면만 조작하면(ex. 슬라이드 이전·다음, 메뉴 열기) `button type="button"`
- 새 창으로 여는 링크(외부 사이트 등)에는 `target="_blank"` 와 `title="새창 열림"` 을 함께 붙인다.
- 링크 주소가 아직 정해지지 않았으면 `href="#none"` 을 사용한다. (`href="#"` 은 클릭 시 페이지가 최상단으로 점프)
  - 주소가 비어 있는 링크는 작업 완료 시 어떤 링크가 미정인지 함께 알린다.
- 폼 전송 주소가 아직 정해지지 않았으면 `action="#"` 을 사용한다. (링크의 `#none` 과 다르다 — 전송은 페이지를 다시 불러오므로 최상단 점프 문제가 없다)
  - 미정인 폼도 작업 완료 시 링크와 함께 알린다.
- label 연결이 구조상 불가능한 input/select/textarea에는 title 속성으로 이름을 제공 (예: 핸드폰 번호 분할 입력 시 '핸드폰 첫째 자리', '핸드폰 둘째 자리', '핸드폰 셋째 자리').
- 아이콘: Font Awesome 6.7.2 기준으로 사용.
- 이미지의 `alt` 는 **그 이미지가 유일한 정보원인지**로 정한다. 모양이 아니라 역할이 기준이다
  - 이미지 옆·아래에 **같은 내용을 전달하는 제목·설명이 있으면 `alt` 를 비운다**(`alt=""`). 채우면 스크린 리더가 같은 내용을 두 번 읽는다 — 썸네일 + 제목으로 이뤄진 목록·카드가 대표적이다
  - 이미지에만 정보가 있으면(주변에 대체할 텍스트가 없음) 문구를 채운다. 시안에서 뽑되 **애매하면 지어내지 말고 작업 완료 시 함께 알린다**
  - 배경·장식용 이미지는 항상 `alt=""`
- 실제 이미지가 아직 없으면 플레이스홀더 `https://placehold.co/{가로}x{세로}` 를 쓴다(`www.` 없이). 크기는 시안에서 잰 그 자리의 크기

## HTML Layout Guide
- **html 기본 레이아웃:** `references/html/html-layout.html`
  - 헤더 또는 푸터 또는 콘텐츠 영역 등 특정 영역을 지정해서 작업 요청할 시 참고하여 작업. (ex. 메인 페이지에 헤더, 푸터를 제외하고 퍼블리싱 작업 요청시 html-layout.html 파일의 main 태그 내용 참고하여 작성)
- **서브 페이지:** `html-layout.html` 의 헤더·푸터·`.wrap` 틀을 같이 쓰고 `wrap_main` 은 뺀다. `<main>` 안은 시안에 있는 영역만 아래 이름으로 잡는다
  - 상단 비주얼 `visual_sub` · 바형 서브 메뉴 `menu_sub` · 좌측 메뉴 `lnb_sub` · 본문 `cont_sub`
  - 좌측 메뉴가 있으면 `lnb_sub` 와 `cont_sub` 를 감싸는 배치 래퍼 `layout_sub` 를 둔다
  - 제목은 `tit_sub` → `tit_sub2` → `tit_sub3`, 서브 공통 클래스는 `.cont_sub` 로 스코프한다

## 자주 쓰는 UI
- **슬라이드 ui:** swiper-11.1.3 버전을 사용하는 것을 전제로 작성.
  - swiper 구조는 `references/html/swiper.html`를 참고하여 작성.
  - swiper 구조와 연동할 스크립트는 작성하지 않아도 되고 `scripts/swiper.js`를 읽어서 html 작성에 참고만 하도록 해.
  - `swiper.js` 는 jQuery 샘플이다. 이 샘플로 스크립트를 쓸 때는 프로젝트에 jQuery 가 연동돼 있는지 확인하고, 없으면 사용자에게 연동을 요청한다
- **탭과 탭패널 연동 ui:** `references/html/tab-container.html`를 참고하여 작성.
- **썸네일 카드 ui:** `references/html/thumbnail.html`를 참고하여 작성.
