# 번역 규칙 — 시안을 코드로 옮기는 법

시안에서 읽은 값은 **그대로 옮기면 틀리는 경우**가 있고, 시안이 정하지 않은 것(다른 화면 폭, 그려지지 않은 내용)은 코드에서 채워야 한다. 이 문서는 시안 도구와 CSS 의 표현 차이, 시안에 없는 폭·내용을 채우는 법, 시안 요소를 코드 자산으로 고르는 법, 그리고 옮기다 갈림길을 만났을 때 묻는 기준을 다룬다.

```
읽기   이 테두리는 요소 안쪽에 그려져 있다          ← references/design/reading-figma.md · reading-img.md
번역   그러니 padding 에서 테두리 두께를 뺀다       ← 이 문서
쓰기   padding: 12px 14px 12px 22px 로 적는다     ← 쓰기 규칙(references/*-guide.md)
```

**"묻는 기준"과 "공통"은 항상 읽고, 형식별 절은 그 형식의 시안일 때만 읽는다.** 원리는 공통에 두고, 형식마다 다른 적용법만 형식별 절에 둔다.

## 묻는 기준
추측해서 진행하면 전부 다시 해야 하는 판단만 묻는다.
- **묻는다** — 시안으로 판단할 수 없고 결과가 크게 갈리는 것. 시안 요소를 코드에서 무엇으로 만들지 선택지가 갈릴 때(아래 "시안 요소를 코드 자산으로 바꿀 때"), 시안에 나타나지 않는 개수·동작이 결과를 좌우할 때
- **묻지 않는다** — 반응형 분기. 시안이 있는 폭을 1:1 로 맞추는 것이 먼저고, 시안이 없는 폭의 분기는 관례대로 넣은 뒤 보고한다(아래 "반응형 분기")

## 공통

### 테두리 — CSS 박스 크기
CSS `border` 는 `box-sizing: border-box` 에서도 padding 바깥에 더해진다. 시안에서 잰 padding·크기를 그대로 쓰면 테두리 두께만큼 커질 수 있으니, 시안의 테두리가 어디 그려졌는지에 맞춰 옮긴다(형식별 절).

### 반응형 분기 — 시안이 있는 폭을 먼저 맞춘다
분기는 사용자에게 묻지 않고 아래대로 넣은 뒤, 넣은 내용을 보고한다. 어느 경우든 **시안이 있는 폭을 1:1 로 맞추는 것이 먼저**다.

**PC 시안만 있을 때**
- 시안 값은 PC 분기(`references/css-writing-guide.md` 의 브레이크포인트 기준 1200 이상)에 그대로 옮긴다
- **PC 분기는 시안 폭이 아니라 1200 부터다** — 한 줄에 놓인 고정 폭·gap 의 합이 1200 의 컨테이너 안쪽 폭(ex. 1200 − 스크롤바 15 − 좌우 padding 60 = 1125)에 들어가는지 쓰기 전에 계산한다. 넘치면 늘어나도 되는 쪽을 유동 트랙(`minmax(0, Npx)`)으로, 그래도 안 되면 줄바꿈 배치로 정한다
  - 실측 예 — 바로가기 8개(1005) + gap(20 × 7 = 140) = 1145 가 1125 를 넘어 1200 에서 글자가 두 줄로 꺾였다
- 좁은 분기는 다단 → 1단으로 접는 것을 기본으로 한다
- **시안에 없는 값을 새로 지어내는 데 품을 쓰지 않는다** — 좁은 분기의 폰트 크기·여백 축소값은 최소한만 둔다. 지어낸 값이 많을수록 대조할 근거가 없는 코드가 늘고, 정작 PC 시안 대조가 뒤로 밀린다

**모바일 시안만 있을 때**
- 시안 값은 기본(분기 없는) CSS 에 옮긴다. 시안 폭(ex. 360)에 맞춘 고정 폭은 화면 폭을 따라 늘어나게 옮긴다
- 넓은 분기는 콘텐츠 최대 너비 안에 가운데 두는 것까지만 하고, **다단으로 펼치는 배치는 지어내지 않는다**. 펼치지 않으면 어색해 보이는 영역은 보고한다

**둘 다 있을 때**
- 모바일 시안은 기본 CSS, PC 시안은 1200 분기에 옮긴다
- 시안이 없는 768 분기는 PC 배치가 768 의 컨테이너 안쪽 폭에 들어가면 PC 배치를, 아니면 모바일 배치를 쓴다(계산 방법은 위 1200 과 같다)

### 배치에 종속된 값 — 좁은 분기로 그대로 옮기지 않는다
시안의 값 중에는 **가로 배치를 전제로 한 것**이 있다. 세로로 쌓이는 분기까지 그대로 따라가면 모양이 깨진다.
- 반복 카드의 일부 모서리만 다른 radius(ex. 3장 묶음의 대각선 바깥 모서리만 작게) — 좁은 분기에서는 균일값으로 되돌리고, 예외 모서리는 시안과 같은 배치가 되는 분기에서만 선언한다
- 위로 삐져나오는 일러스트 — 세로로 쌓이는 분기에서 앞 카드 본문을 덮는다. 스택 분기에서는 카드 사이 `gap` 을 삐져나온 높이 이상으로 벌린다
- space-between 으로 벌어진 간격 — 한 줄일 때만 CSS `justify-content: space-between` 과 같다. 좁은 폭에서 줄이 바뀌면 남는 폭이 빈 공간이 되므로, 시안의 실제 간격(좌표 차)을 `gap` 으로 두고 줄이 바뀌면 늘어날 요소에 `flex-grow` 를 준다
  - 실측 예 — 제목 영역 260 + 간격 74 + 카드 목록 1266 = 1600. 목록을 1266 고정으로 두자 1440 에서 목록이 아래 줄로 내려간 뒤 오른쪽 139px 이 비었다

### 콘텐츠 높이에 따라 변하는 배경 면적
시안의 배경 면적은 콘텐츠 높이에 따라 변한다. **높이를 px 로 박지 말고** 섹션의 `padding-bottom` + 다음 섹션의 음수 `margin-top` 으로 잡으면 분기마다 다시 재지 않아도 된다.

### 줄바꿈
시안에 없는 폭에서는 줄바꿈이 달라진다. 시안의 줄바꿈을 재현해야 하면 `<br>` 대신 **텍스트 폭(컨테이너 padding)** 으로 맞춘다. 분기에서 자연스럽게 다시 흐른다.

### 시안에 없는 내용
시안이 그리지 않은 내용은 **지어내지 않고 자리표시로 두고 보고한다.**
- 셀렉트 option — 시안에 보이는 선택값을 첫 option(`selected`)으로 두고, 나머지는 `옵션1`·`옵션2`
- 링크 주소 — `href="#none"`
- 시안이 한 장만 그린 반복 이미지 — `https://placehold.co/{w}x{h}`(크기는 시안의 그 슬롯 크기)
- 실측 예 — 셀렉트 option 을 그럴듯한 지역명으로 채웠다가 시안에 없는 내용을 지어낸 결과가 됐다

### 시안 요소를 코드 자산으로 바꿀 때
시안의 같은 요소가 코드에서는 여러 방식으로 만들어질 수 있다. **선택지가 갈리면 묻는다.**
- **차트** — 기본은 빈 구조로 둔다(`references/html-structure-guide.md` 의 차트 영역 규칙). 사용자가 요청하면 시안 SVG 를 이미지로 넣는다. 어느 쪽이든 라이브러리가 참조할 `id` 는 붙인다
- **아이콘** — 프로젝트 아이콘 세트에서 형태가 같은 것을 고른다. 시안 아이콘 이름은 다른 세트 기준일 수 있다(ex. `trending-up` → Font Awesome `arrow-trend-up`). 스타일(solid·regular·light)은 시안의 채움·선 두께에 맞춘다. 아이콘용 이미지 에셋이 따로 제공됐다면 폰트 아이콘으로 대체하지 않는다. 아이콘 세트가 없어 SVG 로 그려야 하면(`references/html-structure-guide.md` 의 아이콘 규칙) 피그마는 아이콘 노드를 SVG 로 받아 쓰고(`references/design/reading-figma.md` 의 이미지 에셋 절), 이미지 시안은 형태를 보고 그린다

## 피그마 시안

### 정렬용 프레임을 마크업에서 없앨 때
시안의 프레임 구조와 마크업 구조는 1:1 이 아니다. 정렬·간격만 담당하는 프레임은 마크업 요소로 만들지 않는 게 맞다(무엇이 모듈인지는 `references/css-writing-guide.md` 의 CSS 모듈 규칙).

**단 그 프레임이 들고 있던 고정 폭·최대 폭·정렬은 남는 상위 요소로 옮긴다.** 프레임을 지우는 순간 그 숫자가 조용히 사라진다.
- 실측 예 — 폭 768 인 정렬용 프레임을 지웠더니 그 안의 검색바가 콘텐츠 컨테이너 폭(1600)으로 늘어났다. 768 을 그 섹션 컨테이너의 `max-width` 로 옮겨야 했다

### 테두리 — 안쪽 테두리
피그마의 테두리는 보통 요소 **안쪽**에 그려진다(`strokeAlign` 으로 확인). 시안의 padding 에서 **테두리 두께를 빼서** 옮긴다.
- 실측 예 — 높이 72 인 검색바(padding 14, 테두리 2)를 padding 14 로 옮기면 76 이 된다. padding 12 로 옮겨야 72 다

### 텍스트 박스 — 감싼 프레임과 크기가 다를 때
텍스트 노드의 박스와 그 텍스트를 감싼 프레임의 크기가 다를 수 있다.
- **높이** — 줄 높이·행 높이는 **프레임 쪽**을 옮긴다
  - 실측 예 — 제목 텍스트 박스 31, 감싼 프레임 29 → `line-height: 29px`. 텍스트 박스 값을 쓰면 목록 항목마다 2~3px 씩 밀려 전체 높이가 어긋났다
- **폭** — 자동 폭 텍스트가 감싼 프레임보다 넓으면(메타데이터의 텍스트 폭 > 프레임 폭) 피그마는 밖으로 넘쳐 그리지만, CSS 는 줄바꿈하거나 부모를 텍스트 폭까지 늘린다. 한 줄 유지(`white-space: nowrap`)와 부모 폭 유지(`references/css-writing-guide.md` 의 flex `min-width` 규칙)로 옮긴다
  - 실측 예 — 폭 260 영역의 제목이 273 이라 영역이 273 으로 늘어났다

## 이미지 시안

### 배율 — 시안 px 를 CSS px 로
잰 값은 `references/design/reading-img.md` §0 에서 확정한 배율로 나눠 CSS px 로 옮긴다. 축소 시안은 1px 오차가 `1 ÷ 배율` px 로 커지므로, 나눈 값을 정수로 스냅하고 형제 요소끼리 같은 값을 공유하는지 본다(ex. 401 · 400 · 399 → 400).

### 테두리 — 정렬을 알 수 없는 테두리
이미지 시안은 테두리가 안쪽·바깥 중 어디 그려졌는지 알 수 없다(`references/design/reading-img.md` §2 — 형제 요소와 정렬이 맞는 쪽을 택한다). 잰 바깥 경계를 `box-sizing: border-box` 로 옮길 때 `width = 채움 + 테두리×2` 이고, grid/flex 의 `gap` 도 바깥 경계 기준으로 다시 계산한다.
