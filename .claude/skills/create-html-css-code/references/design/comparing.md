# 대조 기준 — 무엇을 언제 대조하고, 문제를 어떻게 고치고, 무엇을 보고하나

마크업을 다 쓴 뒤 읽는다. **숫자 대조는 보고 전에 매번, 시각 대조는 사용자가 요청할 때만** 한다.

## 숫자 대조 — 매번
코드를 다시 읽는 것으로는 **애초에 옮기지 않은 값**을 찾을 수 없고, 렌더된 크기를 시안 수치와 맞춰 봐야 드러난다. 측정 스크립트가 낸 숫자로만 판단한다.
- **대상** — 고정 폭 요소 전부, 최상위 섹션 높이, 형제 요소 사이 간격
- **가로 넘침** — 시안 폭과 최소 폭(360)·분기 시작 폭(768·1200·1400)에서 가로 스크롤(`scrollWidth > clientWidth`)이 생기지 않는지 본다
- **방법** — 피그마는 `references/design/reading-figma.md` 의 "구현 측정" 절, 이미지는 `references/design/reading-img.md` §8(구현 측정)
- **결과** — 요소 · 렌더 값 · 시안 값 · 차이를 표로 보고에 넣는다
- **문제를 찾았으면** — 아래 "자주 나오는 문제와 조치"

## 시각 대조 — 요청할 때만
스크린샷·시안 캡처를 나란히 보거나 여러 폭의 화면을 눈으로 확인하는 대조. 이미지가 많이 들어가 비용이 크므로 요청 없이는 하지 않고, 보고에 하지 않았다고 밝힌다.

## 자주 나오는 문제와 조치
대조(시안 폭, 좁은 폭·중간 폭)에서 문제를 찾았을 때의 원인과 고치는 법.

### 넘침
- 원인 1순위 — **grid/flex 자식의 `min-width: auto`**. 자식의 min-content(긴 제목 + `padding-right`, `word-break: keep-all` 로 안 쪼개지는 긴 단어)가 트랙보다 크면 트랙을 밀어낸다
- 조치 — `references/css-writing-guide.md` 레이아웃·반응형 절의 `min-width` 규칙대로 고친다. 그래도 넘치면 좁은 분기에서 **min-content 자체**(제목 크기·padding)를 줄인다

### 찌그러짐
- 원인 1순위 — **`left`/`right` 한쪽만 지정한 absolute 요소의 shrink-to-fit** 에, 그 안의 이미지에 걸린 **`max-width: 100%`** 가 겹친 경우. `max-width: 100%` 가 걸린 이미지는 min-content 기여가 0 이라 하한이 사라져 **세로로 늘어난다**
- `img{max-width: 100%}` 는 프로젝트의 리셋·전역 CSS 에 따라 있을 수도 없을 수도 있다 — 원인으로 단정하기 전에 계산 스타일로 실제로 걸려 있는지 확인한다
- 조치 — 그 이미지에 **`max-width: none`**. 컨테이너에 `width` 를 박는 건 원인 제거가 아니다

### 배치 전제가 깨진 값
가로 배치를 전제한 예외값이 세로로 쌓이는 분기까지 따라가 있으면 `references/design/translating.md` 의 "배치에 종속된 값" 대로 좁은 분기에서 되돌린다.

### 시안에 없는 폭에서 줄바꿈이 달라짐
`references/design/translating.md` 의 "줄바꿈" — `<br>` 대신 텍스트 폭으로 맞춘다.
