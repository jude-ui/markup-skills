# create-html-css-code

## Info
- html/css 코드를 작성할 때 참고하기 위한 스킬
- **코드를 어떤 스타일로 적는지**와, 시안이 있을 때 **시안을 읽고 코드로 옮기고 대조하는 법**을 담는다 — 시안이 없으면 "시안을 보고 작성할 때" 절은 건너뛴다
- 시안도 디자인 방향도 없이 작성할 때는 프로젝트에 이미 있는 스타일(리셋·공통 CSS·색 변수)을 쓰고, 없으면 구조가 드러날 만큼만 꾸민다. 화이트 배경, 제목 속 이탤릭 강조 단어, '01/02/03' 번호 섹션 라벨, 모노스페이스 라벨, 알약형(pill) 버튼은 넣지 않는다

## 작업 순서

1. HTML 코드 작성시 `references/html-structure-guide.md`를 읽어 확인
2. CSS 네이밍 작성시 `references/css-naming-guide.md`를 읽어 확인
3. CSS 코드 작성시 `references/css-writing-guide.md`를 읽어 확인
4. **다 쓴 뒤 중복 선언 점검** — 새로 쓴 속성마다 그 선언을 빼도 요소에 적용되는 값이 그대로인지 보고, 그대로면 지운다(`css-writing-guide.md` "값 표기" 첫 항목).

## 상황별로 더하는 단계
조건이 맞을 때만 위 작업 순서에 더한다.

### 기존 사이트 화면 소스를 긁어온 로컬 페이지에서 작업할 때
작업 순서 1번 전에 `references/existing-site-guide.md` 를 읽는다. 클래스명·아이콘·슬라이드를 가이드 기본값으로 정한 뒤에 읽으면 HTML 을 다시 써야 한다

### 화면설계서를 보고 작성할 때
**화면설계서는 시안이 아니다** — 영역 구성·항목·문구·기능 설명만 가져오고, 크기·색·여백은 읽지 않는다. 설계서의 박스·선은 배치를 설명하려고 그린 것이라 실측하거나 숫자 대조하지 않는다. 모양은 시안 없는 작업처럼 프로젝트에 이미 있는 스타일로 정한다.
- 번호 마커·설명 패널 같은 주석은 마크업하지 않는다. 기능 설명(ex. "클릭 시 레이어 팝업")은 구조·동작에 반영한다
- 시안과 함께 받으면 모양은 시안, 내용·기능은 설계서를 따르고, 둘이 다르면 사용자에게 확인한다
- 받은 자료가 설계서인지 시안인지 애매하면 사용자에게 확인한다 — 번호 마커·설명 패널·회색 와이어프레임 박스가 있으면 설계서다

### 시안(피그마·이미지)을 보고 작성할 때
시안 값만 읽거나 대조만 할 때는 이 절의 해당 단계(1. 시안 읽기 또는 4. 대조·보고)만 한다.

1. **시안 읽기** — 피그마면 `references/design/reading-figma.md`, 이미지면 `references/design/reading-img.md` 의 절차대로 읽는다
2. **결과물 위치** — 사용자가 정해 주지 않았으면 프로젝트 규칙을 따르고, 정해진 규칙이 없으면 사용자에게 확인한다
3. **옮기기** — `references/design/translating.md` 를 읽고, 읽은 값을 번역 규칙으로 바꾼 뒤 위 작업 순서의 쓰기 규칙대로 적는다
4. **대조·보고** — 다 쓴 뒤 `references/design/comparing.md` 대로 숫자 대조를 하고 보고한다

### 페이지 목록 파일이 있을 때
**페이지를 추가·수정했고 프로젝트에 페이지 목록 파일(퍼블리싱 목록·인덱스)이 있으면** 그 파일의 비고·기타 칸에 `YYYY-MM-DD 추가` / `YYYY-MM-DD 수정` 처럼 날짜와 추가·수정만 짧게 적는다. 개발에 전달할 때 어떤 페이지가 언제 바뀌었는지 목록에서 바로 보이게 하려는 것이다. 목록 파일이 없으면 하지 않는다
- 목록에 추가·수정을 표시하는 칸(행 색 등)이 있으면 그것도 맞춘다. 이미 신규로 표시된 페이지를 고칠 때는 신규 표시를 그대로 둔다 — 개발 쪽에는 아직 새 페이지다
- 표시를 지우거나 삭제·보류로 바꾸는 것은 사용자가 요청할 때만 한다
