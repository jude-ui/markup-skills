# design-to-markup

시안을 마크업으로 옮기는 **흐름**과, 읽기에도 쓰기에도 속하지 않는 **옮기는 판단**을 담는다.

```
읽기   reading-figma / reading-img    시안에 무엇이 있는지 알아낸다
흐름   design-to-markup (이 스킬)      알아낸 것을 코드로 어떻게 바꿀지 정한다
쓰기   create-html-css-code           바꾼 코드를 어떤 스타일로 적을지 정한다
```

프로젝트 전용 애드온 스킬이 있으면(프로젝트 `CLAUDE.md` 가 함께 호출하라고 지시한다) 각 단계에 그 애드온의 규칙을 더한다. **애드온이 이 스킬이나 쓰기·읽기 스킬의 어느 규칙을 덮어쓴다고 적었으면 애드온을 따른다.**

## 작업 순서
1. **시안 읽기** — 피그마면 `reading-figma`, 이미지면 `reading-img` 를 호출해 읽는다. 시안이 없으면 사용자에게 요청한다
2. **쓰기 규칙 로드** — 마크업을 쓰기 전에 `create-html-css-code` 를 호출한다
3. **결과물 위치** — 사용자가 정해 주지 않았으면 프로젝트 규칙을 따른다. 프로젝트 전용 애드온이 함께 불렸으면 그 문서를 따르고, 정해진 규칙이 없으면 사용자에게 확인한다
4. **옮기기** — 읽은 값을 `references/translating.md` 의 번역 규칙에 따라 구조와 코드로 옮긴다
5. **대조** — 보고 전에 아래 "대조" 절의 숫자 대조를 한다. 시각 대조는 사용자가 요청할 때만
6. **보고** — 아래 "보고" 항목

## 묻는 기준
추측해서 진행하면 전부 다시 해야 하는 판단만 묻는다.
- **묻는다** — 시안으로 판단할 수 없고 결과가 크게 갈리는 것. 시안 요소를 코드에서 무엇으로 만들지 선택지가 갈릴 때, 시안에 나타나지 않는 개수·동작이 결과를 좌우할 때
- **묻지 않는다** — 반응형 분기. 모바일 시안이 없으면 PC 시안을 1:1 로 맞추는 것이 먼저고, 분기는 관례대로 넣은 뒤 보고한다(`references/translating.md`)

## 대조
**숫자 대조는 보고 전에 매번, 시각 대조는 사용자가 요청할 때만** 한다.

### 숫자 대조 — 매번
코드를 다시 읽는 것으로는 **애초에 옮기지 않은 값**을 찾을 수 없고, 렌더된 크기를 시안 수치와 맞춰 봐야 드러난다. 측정 스크립트가 낸 숫자로만 판단하고 스크린샷은 찍지 않는다.
- **대상** — 고정 폭 요소 전부, 최상위 섹션 높이, 형제 요소 사이 간격
- **가로 넘침** — 시안 폭과 최소 폭(360)·분기 시작 폭(768·1200·1400)에서 가로 스크롤(`scrollWidth > clientWidth`)이 생기지 않는지 본다
- **방법** — 읽기 스킬의 "구현과 대조" 절(`reading-figma`) 또는 §8(`reading-img`)
- **결과** — 요소 · 렌더 값 · 시안 값 · 차이를 표로 보고에 넣는다
- **문제를 찾았으면** — 원인·조치는 `references/troubleshooting.md`

### 시각 대조 — 요청할 때만
스크린샷·시안 캡처를 나란히 보거나 여러 폭의 화면을 눈으로 확인하는 대조. 이미지가 많이 들어가 비용이 크므로 요청 없이는 하지 않고, 보고에 하지 않았다고 밝힌다.
