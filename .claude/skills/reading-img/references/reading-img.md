# Img Design Reading Guide

## 목적
시안 이미지(PNG/JPG)만 주어진 상태에서 HTML/CSS 수치를 뽑아낼 때 참고한다.
눈대중이나 `제목 700 / 본문 500` 같은 관습값으로 채우지 말고 **픽셀을 직접 읽어 측정**한다.

읽는 시점 — 시안을 그대로 구현할 때 / 시안과 구현물이 어긋난 원인을 찾을 때 /
폰트 크기·굵기·자간·radius·이미지 위치처럼 눈으로 확정 못 하는 값을 정할 때.

전제: 이미지 라이브러리는 필요 없다. `references/measure.py` 를 스크래치패드에 복사해
`from measure import *` 로 쓴다. **측정 로직을 새로 타이핑하지 말 것.**

이 문서의 핵심 4가지 — 나머지는 전부 이걸 지키기 위한 각론이다.

1. **항목마다 스크립트를 따로 돌리지 않는다.** `survey()` → `font_probe()` → `shot()`/`diff_png()`/`audit()`
   순서로 묶어 왕복을 줄인다.
2. **`ink_box()` 가 `ClippedBox` 를 던지면 그 값은 버린다.** 잘린 값으로 폰트·크기를 판정하면 결론이 통째로 틀어진다.
3. **폰트는 `font_probe()` 한 번으로 종류·크기·굵기·자간을 동시에 확정한다.** 따로 재면 라운드가 3번 돈다.
4. **`TOL` 안에 들어오면 더 재지 않는다** — 텍스트 잉크·컴포넌트 박스 ±1px, 이미지 배치·모서리 반경 ±2px,
   배경 곡선·워터마크 등 장식 ±10px. 더 정밀해져도 화면에서 구분되지 않는다. 남은 시간은 분기 점검에 쓴다.

## 절차 — 이 순서로

시간은 계산량이 아니라 **왕복 횟수**에서 샌다. 앞 패스의 값(배율·잉크박스)을 뒤 패스가 쓰므로 순서는 지킨다.

- **패스0** 에셋 bbox·배율·시안 캔버스 폭 — `alpha_bbox()` 를 전 에셋 루프로
- **패스1** 전 섹션 잉크박스·색 + **모든 면의 테두리** — `survey()` + `edges()`
- **패스2** 폰트 확정(종류·크기·굵기·자간 동시) — `font_probe()`, 텍스트 종류당 1회
- **패스3** 구현 대조 — `shot()` → `survey(ref=)` → `diff_png()` → `audit()`

- **"발견"과 "확인"을 가른다.** 무엇이 있고 어떤 모양인지(발견)만 이미지를 보고,
  맞게 구현됐는지(확인)는 **수치로** 한다. 시안 전체 보기와 차이 블렌드는 각 1회면 충분하다.
  - 확대는 형태 판독이 필요할 때만, **2배를 넘기지 않는다.**
  - 여러 화면폭을 볼 때는 축소해 **한 장으로 합쳐** 읽는다.
- **출력은 결론만.** 색 변화 지점 전부, 전체 ASCII 맵, API 응답 전문을 print 하지 않는다.
- **노력을 눈에 띄는 정도에 맞춘다.** 알파가 옅은 장식 하나에 2D 탐색을 돌리지 않는다.
- 검증용 임시 파일은 작업 완료 시 삭제한다.

### 패스 1 템플릿 — 이대로 복사해 이름·창만 바꾼다

```python
from measure import *
d    = Img('design.png')
PAGE = (0xf5, 0xf5, 0xf5)                 # 시안에서 뽑은 배경색으로 교체
INK  = notnear(PAGE, 20)                  # 밝은 배경 위 잉크
LIGHT= near((255, 255, 255), 70)          # 어두운 면 위 흰 글자

survey(d, [                               # (이름, 그 요소만 들어오는 창, 판정자)
    ('제목',    (x0, y0, x1, y1), INK),
    ('본문',    (x0, y0, x1, y1), INK),
    ('버튼라벨', (x0, y0, x1, y1), LIGHT),
])   # 잘린 항목이 있으면 전부 찍은 뒤 ClippedBox 로 실패한다

edges(d, [                                # 면이 있으면 예외 없이 전부 넣는다
    ('버튼', (x0, y0, x1, y1)),
    ('카드', (x0, y0, x1, y1)),
])
# 버튼  테두리 있음  {'좌': '#dcdce8 1px', '우': ..., '상': ..., '하': ...}
# 카드  테두리 없음
```

## 공통 규칙

### 정확도

- **경계는 서브픽셀(알파 50% 교차점)로 잡는다.** 색 임계값으로 잡으면 안티에일리어싱 픽셀을 안쪽으로 세어
  **크기가 계통적으로 작게 나온다.** `sub_edge()` 가 해준다.
- **`ink_box()` 가 `ClippedBox` 를 던지면 그 값은 버린다.** 창에 닿은 값은 잘린 값이고,
  이 한 번의 무시가 폰트·크기 결론을 통째로 뒤집는다. 창을 20px 이상 넓혀 다시 잰다.
  일부러 자른 변만 `allow='lr'` 로 연다 — **세로(t/b)는 절대 열지 않는다.**
- **이웃 요소가 범위에 들어오면 오염된다.** 측정 범위는 **그 요소만 있는 구간**으로 좁힌다.
- **다른 값의 기준이 될 값은 두 방향(행·열)으로 교차검증한 뒤 쓴다.** 컨테이너 폭, 박스 높이가
  틀리면 그 위에 쌓은 계산이 전부 다시다.
- **측정 도구가 의도한 조건으로 렌더했는지 먼저 확인한다.**
  - headless Chrome 은 **창 폭 하한 500px**. 그보다 좁은 폭은 `audit()` 이 iframe 뷰포트로 우회한다.
    직접 `--window-size=360` 을 주면 500 으로 렌더된다.
  - 뷰포트 에뮬레이션은 **`<meta name="viewport">` 없는 문서에서 980px** 로 잡힌다. 검증용 임시 페이지에도 넣는다.
  - CSS 를 고쳐도 브라우저가 캐싱한다. 값이 안 변하면 **쿼리스트링(`?v=…`)** 으로 무력화하고 `getComputedStyle` 로 확인.

## 0. 측정 전에 먼저 할 일

- **에셋 목록부터 확인한다(시안을 읽기 전에).** 무엇이 이미지로 제공됐는지 알면
  **그 부분은 시안에서 판독할 일이 없다.** 원본에는 가려짐·배경 합성이 없고 크롭·확대 왕복도 필요 없다.
  글자가 든 이미지(배지·로고·인증마크)의 `alt` 문구는 **시안 확대가 아니라 원본 파일에서 읽는다.**
- **에셋의 알파 bbox를 전부 뽑는다**(`alpha_bbox()` 루프 1회). "잉크 박스"(그려진 영역) ≠ "캔버스 박스"(파일 크기).
  **CSS 좌표·크기는 항상 캔버스 박스 기준**이다. 잉크 기준으로 쓰면 여백만큼 어긋난다.
- **시안 캔버스 폭을 확인**하고 모든 좌표를 그 기준으로 기록한다.
- **배율을 확정한다.** 배경 위에 온전히 드러난 에셋 1~2개로 `시안 크기 ÷ 파일 크기`.
  **1x 인지 2x 인지 단정하지 말고 재서 정한다.** 확정 후에는 모든 에셋에 **같은 배율을 고정**한다.

## 1. 폰트 — 종류·크기·굵기·자간을 한 번에 확정한다

크기·종류·굵기를 따로 돌리면 라운드가 3번 돈다. **`font_probe()` 한 번으로 끝낸다.**

```python
font_probe(d, box, '한어절', fg, bg,      # box = 그 문자열의 잉크박스
           [(본문폰트, 600, 26, 0),        # 후보: (family, weight, size, ls)
            (본문폰트, 700, 26, 0),
            (제목폰트, 700, 23, 0)], font_dir='../fonts')
# 시안  w66 h23 den 0.427
#   본문폰트 600 / 26px / ls0  w67 h24 den 0.402  차이 0.0463  ←
#   제목폰트 700 / 23px / ls0  w65 h21 den 0.600  차이 0.1533
```

**차이(실루엣 평균 알파 오차)가 가장 작은 후보가 답이다.** 폭·높이·밀도가 동시에 맞아야 한다.

- **후보 크기는 잉크로 어림한 뒤 ±2px 만 넣는다.** 한글 잉크 높이는 대략 `0.89em`(받침 포함),
  괄호·쉼표가 섞이면 `0.93~1.0em`. `0.7em` 같은 값으로 어림하면 크게 틀린다.
- **굵기 판정은 한 어절짜리 짧은 문자열로 한다.** 긴 문장은 자간 누적 오차가 실루엣 차이를 지배해
  굵기 신호를 덮는다. 크기·자간은 긴 문자열로, 굵기는 짧은 문자열로 각각 확정한다.
- **후보 굵기는 300~900 을 전부 연다.** 한글 폰트도 Light(300) 를 보조 문구·부제·라벨에 쓰는 경우가 있다.
  "본문에 Light 는 잘 안 쓴다" 같은 선입견으로 후보에서 빼면 한 단계 무겁게 오판한다.
- **후보 렌더 조건을 대상 페이지와 똑같이 맞춘다** — 배경색과 **font-smoothing** 둘 다.
  리셋의 `-webkit-font-smoothing: antialiased` 를 빼고 렌더하면 획이 두꺼워져
  **모든 굵기가 한 단계 가볍게 판정된다**(700 을 600 으로, 800 을 700 으로).
  `font_probe(..., smoothing=True)` 가 기본이며, 대상 페이지가 그 속성을 쓰지 않을 때만 끈다.
- 한글은 폭으로 굵기를 구분할 수 없다(주요 한글 폰트는 400↔900 폭 차이가 2% 미만이다).
  단 **숫자·영문은 굵기에 따라 폭이 달라지므로, 숫자가 섞인 문자열은 폭이 결정적 근거**가 된다.
- **`잉크높이로 구한 fs` 와 `폭으로 구한 fs` 가 5% 이상 어긋나면 폰트가 다르다는 신호다.**
  이때 자간으로 폭을 억지로 맞추지 말 것. 폰트 오판을 덮어버린다.
- **양수 자간이 필요하다는 결론이 나오면 거의 항상 폰트가 틀린 것이다.** 한글 디자인의 자간은 보통 0 또는 음수.
- 프로젝트에 그 폰트가 없으면 자간을 지어내 맞추지 말고 **"기본 폰트가 아닌 것 같다"고 알리고 확인받는다.**
- 시안 툴 래스터화는 브라우저와 달라 밀도 절대값이 한 단계 어긋날 수 있다.
  **못 정하면 폭·높이가 맞는 후보**를 택한다.

## 2. 테두리·그림자 — 값보다 "있는지"를 먼저 확인한다

1px 테두리는 눈으로 훑으면 거의 안 보이고, 채움색의 옅은 변형(tint)이면 더 그렇다.
**채움색을 뽑았다고 끝난 게 아니다. 면이 있으면 예외 없이 `edges()` 를 돌린다** — 패스 1에서 한 번에.

- 원리: 변의 **중앙**에서 바깥→안으로 색을 나열한다(모서리는 안티에일리어싱이 섞여 못 쓴다).
  `배경색 → 중간색 1~2px → 채움색` = 테두리 있음 / `배경색 → 채움색` = 없음.
  중간색이 **배경↔채움의 혼합(0~1 보간)** 이면 안티에일리어싱, 그 선을 벗어나면 진짜 테두리색이다.
- **네 변을 모두** 확인한다(`edges()` 는 한 변에만 있으면 경고한다).
  **상태(기본/활성/hover)마다 테두리 색이 다르다** — 활성 항목은 반드시 따로 잰다.
- 이미지 에셋(메달·배지 등)은 자기 테두리(금테 등)를 갖고 있어 "테두리 있음"으로 잡힌다. CSS 테두리와 구분할 것.
- 테두리를 찾았으면 **크기를 다시 잰다** — 채움 크기와 테두리 두께를 따로 기록하고, 요소 사이 간격도 바깥 경계 기준으로 다시 잰다.
  CSS 로 옮기는 식은 `design-to-markup` 번역 규칙.
- 디자인 툴 stroke 는 inside/center/outside 가 있어 1px 어긋나 보인다. **형제 요소와 정렬이 맞는 쪽**을 택한다.
- 같은 방식으로 존재를 확인할 것 — `box-shadow`(바깥 2~10px 스캔), `linear-gradient`(면 안쪽 색이 일정한지), `outline`.

## 3. 색상

- **한 점만 찍지 말고 영역의 최빈색을 쓴다.** 일러스트·텍스트가 겹치면 한 점은 얼마든지 틀린다.
- 배경색은 텍스트·이미지가 없는 안쪽 여백에서 뽑는다.
- 텍스트가 반투명인지 의심되면 **최빈색에 순색(`#ffffff` 등)이 있는지** 본다. 없으면 알파가 걸린 것이다.

## 4. 모서리 radius

- **요소마다 4모서리를 각각 잰다.** 한 모서리만 재고 복사하지 않는다.
- 반복 리스트(카드·배너)는 **첫/끝 항목이 다를 수 있다고 전제**하고 전 항목 × 4모서리를 잰다.
  값이 하나라도 다르면 오차가 아니라 **디자인 의도**다(예: 3장 묶음의 대각선 바깥 모서리만 작게).
  - 그 의도가 **배치에 종속된 것인지** 판단해 함께 기록한다(분기로 옮기는 법은 `design-to-markup` 번역 규칙).
- **색 임계값으로 경계를 잡지 않는다.** "순백 N줄 연속" 같은 판정은 몇 px 씩 안쪽으로 밀린다.
  `radius_fit()` 이 서브픽셀 경계로 피팅하고, **모서리 끝 몇 px(접선 지점)는 표본에서 뺀다.**
- **표본 구간에 다른 요소가 없어야 한다.** 카드 모서리 근처에 제목·일러스트가 걸리면 RMSE 가 수십 px 로 튄다.
  `radius_fit` 의 `span` 은 예상 반경의 1.5배 정도로 좁게 잡는다.
- **확정은 후보 렌더 대조로 한다.** 후보 반경들을 같은 색으로 렌더해 **같은 서브픽셀 코드**로 모서리 프로파일을 뽑고
  시안과 평균 오차를 비교하면 1px 단위로 갈린다. 이때 **직선변 위치가 시안과 일치하는지 먼저 확인**해
  계통 오차를 제거한다(통제군). 직선변이 어긋나 있으면 모서리 비교는 의미가 없다.
- 결과는 **디자인 툴이 쓸 법한 정수로 스냅**하고 **여러 요소가 같은 토큰을 공유하는지** 본다.
  23.2 / 23.3 / 23.4 로 흩어지면 다른 값이 아니라 같은 `24px` 이다.

## 5. 곡선·배경 도형

- **점 2~3개로 모델을 세우지 않는다.** 경계 전체를 훑고 나서 모델을 정한다.
- **콘텐츠가 겹치지 않는 열(column)만** 골라 경계를 추적한다.
- 경계값이 한동안 일정하면 **그 구간은 직선**이고 곡선은 모서리에만 있다.
- **원(단일값)부터 본다.** RMSE 2px 이하면 채택하고 `/` 타원 문법은 쓰지 않는다.
  타원은 원이 뚜렷이(RMSE 1.4배 이상) 안 맞을 때만.
- **곡선이 수직/수평 접선이 되는 끝점을 반경의 기준으로 삼지 말 것.**
  그 열은 커버리지가 여러 행에 퍼져 50% 교차점이 의미를 잃는다. 여기서 읽은 값으로 세로 반경을 고정하면
  가로 반경이 억지로 늘어나 **원이 타원으로 둔갑한다.**
  (접선점 하나를 표본에 넣어 `R 203px` 원을 `220px/184px` 타원으로 오판한 예 — RMSE 1.4 → 7.0)
- 장식이므로 ±10px 안에 들어오면 더 파지 않는다.

## 6. 가려진 이미지 배치

가려진 일러스트는 **드러난 끝을 이미지 끝으로 착각하기 쉽고**, 투명 여백 때문에 **잉크 끝 ≠ 캔버스 끝**이다.

**여백은 시안과 대조하지 않는다.** 투명해서 안 보이니 맞출 수가 없다.
**잉크끼리 맞추고 여백은 소스 파일에서 읽어 빼면** 된다(`place()` 가 둘 다 해준다).

- `top = 시안 잉크 상단 − (소스 잉크 상단 × 배율)` — **소스 여백이 여기서 상쇄된다.**
  노출된 변이 상단이 아니면 **그 변으로 바꿔서** 뺀다.
- **표본 산포(`spread`)가 곧 신뢰도다.** ≤3px 이면 채택. 크면 `top` 을 고정한 채 `left` 만 1D 탐색한다.
- **CSS 크기는 `캔버스 × 배율`.** `<img>` 는 투명 여백까지 그 크기에 욱여넣으므로,
  눈에 보이는 잉크 크기를 주면 **`잉크 ÷ 캔버스` 비율만큼 그림이 작아진다.**
- 잘려 보이는 쪽이 **부모의 `overflow: hidden` 때문일 수 있다.** 잘린 끝은 요소 경계지 이미지 끝이 아니다.
- 사방이 다 가려져 기준 변이 없을 때만 2D 탐색으로 돌아가고, 그래도 안 맞으면
  **시안 이미지가 제공된 에셋과 다를 가능성**을 의심하고 보고한다.

## 7. 아이콘 — 라이브러리 티어부터 확인한다

작은 아이콘은 눈으로 보면 다 비슷하다. **비슷한 걸 골라 반전·회전으로 맞추기 전에, 프로젝트의 아이콘 세트에 정답이 있는지 확인한다.**

- **Font Awesome 은 티어(Pro/Free)를 먼저 본다.** CSS 첫 주석에 적혀 있고, webfonts 디렉터리에 실제 보유 스타일이 있다.
  Pro 에만 있는 아이콘이 정답인 경우가 많다(`fa-megaphone`, `fa-phone-rotary` 등).
  webfont 파일이 없는 스타일은 클래스가 있어도 렌더되지 않는다.
  - **유사 아이콘을 고른 뒤 `transform: scaleX(-1)` 같은 보정을 넣고 있다면 거의 항상 잘못 고른 것이다.**
- 후보는 **큰 크기(60~80px)로 한 줄에 나열해 렌더**하고 눈으로 형태를 고른다(왕복 1회).
- 확정은 **같은 배경색 위 1x 실루엣 대조**로 한다. **잉크 bbox 가 시안과 일치하는 font-size 가 정답 크기다.**

## 8. 검증 — 구현 후 반드시 대조

좌표 델타·차이 픽셀 수·`audit` 결과로 보는 숫자 대조는 매번 한다. 차이 맵·스크린샷 이미지를 열어 눈으로 보는 시각 대조는 사용자가 요청할 때만 한다(`design-to-markup` 대조 절).

### 8-1. 시안 폭에서 대조

```python
W, H = d.w, d.h                                  # 시안 캔버스 크기
shot('index.html', W, H + 20, 'impl.png')        # 1x 스크린샷
survey(d, SPECS, ref=Img('impl.png'))            # 패스1의 SPECS 재사용 → 좌표 델타
print(diff_png('design.png', 'impl.png', size=(W, H)))       # 차이 맵 + 픽셀 수
```

- **텍스트는 안티에일리어싱 차이로 항상 옅게 남는다.** 1px 어긋나면 얇은 획은 통째로 밝아진다.
  **면·모서리·이미지가 밝게 남으면 실제 오류**다.
- 반복 검증은 이미지가 아니라 **좌표 델타와 차이 픽셀 수**로 한다.
- **차이 픽셀 수로 굵기를 판정하지 말 것.** 얇을수록 잉크가 적어 무조건 줄어든다 — 가볍게 오판한다.
  굵기는 `density()` 비교로만 확정한다.
- **밀도는 두 이미지의 각자 잉크박스에서 뽑는다.** 가운데 정렬처럼 위치가 다른 요소를 같은 고정 박스로 재면
  여백만 세어 밀도가 통째로 어긋난다.

### 8-2. 좁은 폭·중간 폭

`audit('index.html', widths=(360, 768, 1200, 1400, 시안폭))` 한 번으로
**최소 폭·각 분기 경계·중간 폭**의 넘침과 찌그러짐을 동시에 본다.
일부러 화면 밖으로 빼는 장식 요소가 있으면 그 클래스명을 `skip=(...)` 에 넣는다.

- 무엇을 보나 — **넘침**(가로 스크롤·트랙 밀림), **찌그러짐**(이미지·박스가 세로로 늘어남),
  **배치 전제가 깨진 값**(가로 배치를 전제한 예외값이 세로 분기까지 따라감), **줄바꿈 변화**(시안에 없는 폭)
- 찾은 뒤의 원인·조치는 `design-to-markup` 의 `references/troubleshooting.md` 와 번역 규칙(`references/translating.md`)
