# 시안 읽기

피그마 MCP 로 시안을 읽을 때의 도구 선택과 주의사항.

**피그마 파일은 고정되어 있지 않다.** 사용자에게 공유 URL 을 받아 fileKey 를 추출한다. URL 이 없으면 요청할 것.

```
https://figma.com/design/{fileKey}/{fileName}?node-id={a}-{b}
                          ↑ fileKey        ↑ nodeId (a:b 형태로 변환)
```

**마스터를 고쳤다면 게시가 먼저다.** 라이브러리 게시와 시안의 라이브러리 업데이트는 **Plugin API 로 불가**하므로 사용자에게 피그마 앱에서 직접 게시해달라고 요청한다. 게시 전까지 시안은 **옛 구조 그대로**라, 그 상태로 읽으면 고치기 전 값을 마크업으로 옮기게 된다.
- 반영됐는지는 구조로 판별한다 — 그 슬롯이 `INSTANCE` 인가 / 새 속성이 `componentProperties` 에 있는가

## 도구 선택

```
get_metadata        노드 트리(이름·타입·위치·크기). 구조 파악의 출발점
get_design_context  선택 영역의 상세 스펙이 필요할 때
get_variable_defs   시안이 쓴 색·토큰 확인
get_screenshot      전체 레이아웃 감 잡기 · 이미지 에셋 받기(에셋 절)
```

`get_design_context` 는 호출 전에 피그마 MCP 의 `figma-design-to-code` 안내를 불러오라고 요구한다. 불러오되, 이 스킬 세트와 겹치는 규칙(에셋 받기·차트·컴포넌트 사용·값의 기준)은 이 스킬 세트를 따른다.

스크립트로 직접 훑을 때 **`node.query()` 셀렉터는 한글 이름을 못 받는다**(`Invalid selector`). 한글 레이어명은 `findAll(n => n.name === '…')` 로 찾는다.

**스크린샷으로 값을 추측하지 말 것.** 여백·색상·폰트 크기는 위 도구로 실제 값을 읽는다.

## 놓치기 쉬운 것

### 인스턴스의 레이어 오버라이드
`componentProperties` 는 variant·불리언·텍스트·인스턴스 스왑만 담는다. **색상처럼 레이어에 직접 준 오버라이드는 잡히지 않아**, 디자이너가 컴포넌트 기본값을 바꿔 쓴 부분을 통째로 놓친다.

인스턴스가 있는 영역은 `get_design_context` 로 실제 값을 확인한다 — `componentProperties` 만 보고 끝내지 말고 해당 인스턴스의 `fills` 와 `boundVariables` 를 직접 읽는다(변수 바인딩이면 변수 이름도 함께 기록한다).

### 인스턴스의 크기 오버라이드
`componentProperties` 에는 **폭·높이가 없다.** 컴포넌트 기본이 폭을 꽉 채우는 요소(입력창·셀렉트 등)는 시안에서 좁혀 놓아도 속성만 보면 알 수 없어, **폭을 통째로 빠뜨리게 된다.**

인스턴스의 `layoutSizingHorizontal` 이 `FIXED` 면 실제 `width` 를 읽어 둔다.

**단 위는 인스턴스 `루트` 얘기다. 인스턴스 `자식`은 크기를 바꿀 수 없다** — `resize()` 계열 4가지 모두 무시되고 피그마 UI 에서 드래그해도 안 된다(실측). 그래서 컴포넌트 안쪽 요소의 크기 변형(안쪽 아이콘 크기 등)은 **시안에 아예 나타날 수 없다.** 코드에 조정 수단이 있어도 시안에서 그 케이스를 찾지 말 것.

### 스왑이 남긴 낡은 높이 — 위와 반대로 **옮기지 않는다**
`INSTANCE_SWAP` 슬롯은 컴포넌트를 바꿔도 **이전 점유 컴포넌트의 높이를 `FIXED` 로 붙들고 있다**(실측: 높이 40 컴포넌트를 30 짜리로 스왑해도 슬롯은 40 유지). 슬롯만 크고 안쪽은 작아 시안이 세로로 어긋나 보인다.

디자이너가 정한 크기가 아니라 스왑 잔여물이므로 **읽은 값으로 기록하지 않는다.** 슬롯의 `layoutSizingVertical` 이 `FIXED` 인데 그 높이가 안쪽 인스턴스의 자연 높이와 다르면 이 경우다. 의도적으로 높이를 키운 시안과 구분이 안 되면 사용자에게 확인한다.

### 대상 노드 밖의 형제·부모 노드
대상 프레임의 서브트리만 보면 **겹쳐 있는 장식 이미지·배경 요소를 통째로 놓친다.** 피그마는 z-order 와 트리 구조가 일치하지 않아, 화면상 특정 섹션 위에 있어도 그 섹션의 자식이 아닐 수 있다.

`get_metadata` 결과에서 **최상위 자식 전체를 y 좌표로 훑어** 대상 영역과 겹치는 노드를 먼저 확인한다.

### 혼합 스타일 텍스트
한 텍스트 노드에 굵기가 섞여 있으면 `node.fontName` 이 `figma.mixed` 라 스타일을 읽을 수 없다. 이걸 놓치면 부분 굵기(ex. 앞부분만 Bold)를 통째로 놓친다.

```js
node.getStyledTextSegments(['fontName', 'fontSize'])
```

구간별로 읽어 각 구간의 `fontName.style` 을 확인한다. Regular 400 / Medium 500 / SemiBold 600 / Bold 700 / ExtraBold 800.

## 이미지 에셋

### 무엇을 받고 무엇을 플레이스홀더로 두나

셋으로 갈린다. **전부 받으려 하지 말 것** — 시안이 그리지 않은 자리까지 받을 수는 없다.

- **프로젝트가 이미 가진 에셋** → 받지 않고 프로젝트의 실제 경로로 참조한다
- **시안에 실제로 보이는 운용성 이미지**(썸네일·사진) → 받아서 저장한다
- **시안에 안 보이는 자리**(슬라이드 2번째 이후처럼 시안이 한 장만 그린 경우) → `https://placehold.co/{w}x{h}` 로 둔다. 크기는 시안에서 잰 그 슬롯의 크기

### 받는 방법

**`get_screenshot` 의 `contentsOnly: true` 로 받는다.**

`download_assets` 의 `export` 는 **투명 배경을 흰색으로 구워낸다**(원본에 알파가 있어도 사라짐). 그대로 쓰면 배경 위에 흰 사각형이 생긴다.

받은 뒤 알파 채널이 살아 있는지 반드시 확인한다. 같은 이미지가 여러 노드에 쓰였을 수 있으니 해시를 비교해 중복을 제거한다.

`get_screenshot` 은 노드 원본 크기까지만 렌더되어 확대(@2x)가 안 된다. 고해상도가 필요하면 디자이너에게 별도 요청한다.

**SVG 로 받는 벡터(차트·일러스트)** — `download_assets` 의 SVG 는 **상위 프레임의 배경색까지 `<rect>` 로 구워 넣는다.** 그대로 쓰면 그림 뒤에 배경 사각형이 생긴다.
- 지우는 것은 배경 `<rect>` 만 — 크기가 SVG 캔버스나 상위 프레임과 같고, 채움이 그 프레임 배경색인 것. 차트 막대처럼 그림 자체가 `<rect>` 일 수 있어 일괄 삭제하지 않는다
- **`<clipPath>`·`<mask>` 안의 `<rect>` 는 지우지 않는다** — 잘라내기 영역이라 지우면 그것을 참조하는 그림 전체가 사라져 빈 이미지가 된다
- 고친 뒤 브라우저에서 렌더해 배경이 없어졌는지, 그림이 그대로 보이는지 확인한다

### 어디 두나

저장 위치와 마크업의 참조 경로는 **프로젝트 규칙**을 따른다. 프로젝트 전용 애드온 스킬이 함께 불렸으면 그 문서를 따르고, 정해진 규칙이 없으면 사용자에게 확인한다.

## 구현과 대조

마크업을 만든 뒤 **보고하기 전에** 시안 수치와 렌더 결과를 맞춰 본다. 코드를 다시 읽는 것으로는 **애초에 옮기지 않은 값**을 찾을 수 없다 — 렌더된 크기를 시안 수치와 대조해야 드러난다.

### 기준값은 프레임 좌표에서 읽는다
- `get_metadata` 의 프레임 `x`·`y`·`width`·`height` 를 기준값으로 쓴다
- `get_design_context` 가 주는 코드의 여백 값은 프레임 좌표와 다를 수 있다(실측: `py-[48px]` 로 나왔지만 자식 y=54·프레임 높이 148 이라 실제 여백은 54). 둘이 어긋나면 **프레임 좌표를 믿는다**
- 텍스트는 글자 박스와 그 텍스트를 감싼 프레임의 높이가 다를 수 있다. 줄·행 높이는 프레임 쪽을 기준으로 대조한다

### 무엇을 대조하나
- **고정 폭 요소 전부** — `layoutSizingHorizontal: FIXED` 인 프레임, 그리고 부모보다 좁은 정렬용 프레임. 정렬용 프레임은 마크업에서 사라졌을 수 있어 가장 잘 놓친다
- **섹션 높이** — 최상위 섹션 프레임마다
- **간격** — 형제 프레임 사이 좌표 차이

### 어떻게 재나
- 시안 폭과 같은 뷰포트에서 렌더하고 `getBoundingClientRect()` 로 잰다. 세로 스크롤바가 있으면 콘텐츠 폭이 뷰포트보다 좁다(1920 뷰포트에서 약 1905)
- 결과는 **표로** 남긴다 — 요소 · 렌더 값 · 시안 값 · 차이
- **스크린샷은 찍지 않는다** — 숫자로만 판단한다. 화면을 눈으로 비교하는 시각 대조는 사용자가 요청할 때만 한다(`design-to-markup` 대조 절)
- 여러 폭의 가로 넘침은 같은 출처의 페이지를 폭별 iframe 으로 띄워 스크립트 한 번에 잰다(`scrollWidth - clientWidth`). 폭마다 창 크기를 바꾸는 것보다 호출이 적다
- 테두리가 있는 요소는 피그마의 테두리 정렬(`strokeAlign`)을 함께 확인한다. 차이가 테두리 두께만큼이면 읽기가 아니라 옮기는 쪽 문제다(`design-to-markup` 의 번역 규칙)

### 브라우저 확인 함정
브라우저 도구로 확인할 때 **측정이 아니라 판독**에서 어긋나는 함정이 둘 있다(Claude 데스크톱 앱의 브라우저 패널에서 확인).
- **가시성은 계산 스타일로 판정하지 않는다** — `getComputedStyle` 이 `opacity: 0`·`visibility: hidden` 으로 나와도 실제로는 보이는 경우가 있다(CSSOM 순회도 규칙을 못 찾는다). 멀쩡한 요소를 결함으로 보고하게 된다. 보이는지는 스크린샷으로 본다. `getBoundingClientRect` 의 크기·좌표는 정상이다
- **스크롤한 상태의 스크린샷은 빈 이미지가 나온다**(`scrollY: 0` 이면 정상) — 다른 영역을 `display: none` 으로 감춰 **대상을 문서 최상단에 올린 뒤** 촬영한다
